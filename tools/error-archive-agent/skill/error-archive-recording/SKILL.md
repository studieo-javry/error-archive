# Error Archive 자동 기록(Automatic Resolution Capture)

## 목표
AI 가 참여한 **하나의 의미 있는 문제 해결 과정**을 **하나의 Capture** 로 남긴다. 발견 주체(AI/사용자)와
수정 방향 결정 주체(AI/사용자)에 관계없이 기록한다. 사용자는 기록 작성이 아니라 **최종 검토**에 집중한다.

## 무엇을 기록하는가
다음 두 상황 모두 대상이다.

- **상황 A (AI 가 발견):** 테스트·빌드 실패나 예외를 AI 가 발견 → 원인 조사 → 수정 → 재검증.
- **상황 B (사용자가 제보):** 사용자가 동작 이상/버그를 알려줌 → AI 가 조사 → (사용자 또는 AI 가) 수정 방향
  결정 → 수정 → 재검증.

기록하지 않는 것: 단순 코드 질문·설명 요청, 의도적으로 실패를 확인하는 테스트, 일시적 환경 오류(네트워크 끊김 등),
잡담.

## 절차
1. **진행 중 Capture 확인** — `capture_list_open` 을 먼저 호출한다. 지금 다루는 문제가 기존 진행 중 Capture
   와 **같은 버그의 연속**이면 그 `captureUuid` 를 재사용하고, **원인이 다른 별개 문제**면 새로 시작한다.
   (한 버그 = 한 Capture. 수정 방법을 여러 번 바꿔도 Capture 는 하나이고 Attempt 가 여러 개다.)
2. **시작** — 새 문제면 `capture_start` 로 OPEN 초안을 만든다(증상·기대 동작·발견 경위). 근거 없는 원인 단정은
   넣지 않는다.
3. **관련 이벤트 연결** — `capture_list_events` 로 수집된 Hook 이벤트(실패한 명령·수정·재실행 등)를 확인하고
   `capture_link_events` 로 이 Capture 에 연결한다.
4. **조사·시도 기록** — 시도마다 `capture_add_attempt`(result = SUCCEEDED/FAILED/INCONCLUSIVE, 무엇을 했고
   무엇을 알았는지). 실패한 시도도 남긴다(나중의 교훈).
5. **사용자 결정 보존** — 사용자가 수정 방향을 직접 골랐다면, 그 선택과 **이유**를 같은 Capture 에 기록한다.
   "사용자가 B안을 선택했다" 는 사실을 AI 의 해결책으로 둔갑시키지 말 것(판단의 출처를 유지).
6. **해결 기록** — 해결에 기여한 시도를 가리키는 `capture_add_solution`(검증 명령·결과 포함).
7. **봉인** — 한 번의 문제 해결 작업이 끝나면 `capture_complete` 로 READY_FOR_REVIEW 로 봉인한다.
   - 사용자가 **계획만 요청하고 수정은 미착수**했거나 아직 조사 중이면 봉인하지 않는다(OPEN 유지).
   - 조사했지만 **끝내 해결하지 못한** 경우에도, 조사 내용과 미해결 사유가 정리됐다면 봉인할 수 있다(결과를
     미해결로 명확히 남긴다).

## 경계
- 정식 **Case 반영은 사용자 검토 단계**에서 이뤄진다. AI 는 Capture 작성·봉인까지만 담당하고 Case 를 확정하지
  않는다.
- 세션 종료(Stop) 자체가 봉인 사유는 아니다. 실제 해결 작업이 끝났는지로 판단한다.
- 하나의 세션에서 서로 다른 버그를 여러 개 해결했다면 Capture 도 그만큼 분리한다.
